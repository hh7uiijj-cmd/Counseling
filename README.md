# ระบบห้องให้คำปรึกษา (Counseling Booking System)

เว็บแอปสำหรับจองคิวเข้ารับคำปรึกษา ประกอบด้วย:

- **หน้าเว็บสำหรับผู้ใช้บริการ** — ปฏิทินแสดงวันว่าง/ไม่ว่าง รายชื่อผู้ให้คำปรึกษาในแต่ละวัน และฟอร์มจองคิว
- **ระบบแอดมิน** — จัดการผู้ให้คำปรึกษา, สร้าง/ลบคิวว่าง (รองรับสร้างซ้ำหลายวัน), จัดการวันหยุด, ดู/อนุมัติ/ยกเลิกการจอง
- **แจ้งเตือนเข้า LINE กลุ่ม** — เมื่อมีคนจองคิวใหม่ ระบบจะส่งการ์ด Flex Message ไปยังกลุ่ม LINE ที่ตั้งค่าไว้ทันที พร้อมปุ่ม **ยืนยัน/ยกเลิก** ที่กดได้จากในแชทกลุ่มเลย และสมาชิกในกลุ่มพิมพ์ "ตารางวันนี้"/"ตารางพรุ่งนี้" เพื่อให้บอทตอบกลับตารางคิวแบบการ์ดปฏิทินได้
- **อีเมลยืนยันอัตโนมัติ** — เมื่อการจองถูกยืนยัน (ไม่ว่าจะกดยืนยันจากหน้าแอดมินหรือกดปุ่มในไลน์กลุ่ม) ระบบจะส่งอีเมลยืนยันไปยังอีเมลของผู้จองโดยอัตโนมัติ (ผ่าน Resend)
- **แท็กชื่อผู้ให้คำปรึกษาในไลน์กลุ่ม** — ถ้าตั้งค่า LINE User ID ของผู้ให้คำปรึกษาแต่ละคนไว้ในหน้าแอดมิน เมื่อมีคิวใหม่เข้ามาสำหรับคนนั้น บอทจะ @แท็กชื่อในกลุ่มให้อัตโนมัติ

สร้างด้วย Next.js 16 (App Router) + Prisma 7 + PostgreSQL + Tailwind CSS

> หมายเหตุ: LINE Notify ปิดให้บริการไปแล้วตั้งแต่ มี.ค. 2025 ระบบนี้จึงใช้ **LINE Messaging API** ผ่าน LINE Official Account แทน

## เริ่มต้นใช้งาน (Development)

### 1. ติดตั้ง dependencies

```bash
npm install
```

### 2. ตั้งค่าฐานข้อมูล PostgreSQL

แก้ไข `DATABASE_URL` ในไฟล์ `.env` ให้ชี้ไปยังฐานข้อมูล PostgreSQL ของคุณ จากนั้นรัน migration:

```bash
npx prisma migrate dev
```

### 3. สร้างบัญชีแอดมินเริ่มต้น + ข้อมูลตัวอย่าง

```bash
npm run db:seed
```

ค่าเริ่มต้น: username `admin` / password `changeme123` (กำหนดผ่าน `SEED_ADMIN_USERNAME` / `SEED_ADMIN_PASSWORD` ได้) — **กรุณาเปลี่ยนรหัสผ่านหลังเข้าสู่ระบบครั้งแรก**

### 4. รันเซิร์ฟเวอร์

```bash
npm run dev
```

เปิด [http://localhost:3000](http://localhost:3000) สำหรับหน้าเว็บผู้ใช้บริการ และ [http://localhost:3000/admin/login](http://localhost:3000/admin/login) สำหรับหน้าแอดมิน

## Environment Variables

ดูตัวอย่างทั้งหมดใน `.env`:

| ตัวแปร | คำอธิบาย |
| --- | --- |
| `DATABASE_URL` | connection string ของ PostgreSQL |
| `SESSION_SECRET` | ค่าลับสำหรับเซ็นชื่อ session cookie ของแอดมิน (ควรสุ่มค่าใหม่ในโปรดักชัน) |
| `LINE_CHANNEL_ACCESS_TOKEN` | Channel access token ของ LINE Official Account |
| `LINE_CHANNEL_SECRET` | Channel secret สำหรับตรวจสอบลายเซ็น webhook |
| `LINE_GROUP_ID` | Group ID ของกลุ่ม LINE ที่ต้องการรับการแจ้งเตือน |
| `APP_BASE_URL` | URL สาธารณะของเว็บแอป ใช้สร้างลิงก์ในข้อความ LINE |
| `RESEND_API_KEY` | API key จาก [Resend](https://resend.com) สำหรับส่งอีเมลยืนยันการจอง (ถ้าไม่ตั้งค่า ระบบจะข้ามการส่งอีเมลโดยไม่ error) |
| `RESEND_FROM_EMAIL` | อีเมลผู้ส่ง (ไม่บังคับ — ต้องเป็นโดเมนที่ verify กับ Resend แล้ว ถ้าไม่ตั้งจะใช้ `onboarding@resend.dev`) |

## ตั้งค่าการแจ้งเตือน LINE กลุ่ม

1. สร้าง LINE Official Account และเปิดใช้งาน Messaging API ที่ [LINE Developers Console](https://developers.line.biz/console/)
2. คัดลอก **Channel access token** (long-lived) และ **Channel secret** ใส่ในไฟล์ `.env`
3. เชิญบัญชี Official Account เข้ากลุ่ม LINE ที่ต้องการรับแจ้งเตือน
4. ตั้งค่า Webhook URL เป็น `https://<your-domain>/api/line/webhook` แล้วเปิดใช้งาน "Use webhook"
5. พิมพ์คำว่า `รหัสกลุ่ม` ในกลุ่มที่เชิญบอทเข้าไป บอทจะตอบ Group ID กลับมาในแชททันที นำไปใส่ใน `LINE_GROUP_ID` (ไม่ต้องเปิด log เซิร์ฟเวอร์)
6. รีสตาร์ทเซิร์ฟเวอร์ แล้วไปที่หน้า **แอดมิน > ตั้งค่า** เพื่อกดส่งข้อความทดสอบ

เมื่อมีการจองใหม่เกิดขึ้น ระบบจะส่ง Flex Message รูปการ์ดปฏิทินไปยังกลุ่มโดยอัตโนมัติ พร้อมปุ่ม **ยืนยัน**/**ยกเลิก** ที่สมาชิกกลุ่มกดได้ทันทีจากในแชท (ระบบจะอัปเดตสถานะการจองและแจ้งกลับเข้ากลุ่มทันทีที่กด) และสมาชิกกลุ่มสามารถพิมพ์ "ตารางวันนี้" หรือ "ตารางพรุ่งนี้" เพื่อให้บอทตอบกลับตารางคิวของวันนั้นแบบการ์ดได้ทันที

> ⚠️ หมายเหตุ: ปุ่มยืนยัน/ยกเลิกในไลน์กลุ่มกดได้โดยสมาชิกทุกคนในกลุ่ม เนื่องจาก LINE Messaging API ไม่มีระบบสิทธิ์รายบุคคลในกลุ่ม จึงควรเชิญเฉพาะเจ้าหน้าที่ที่เกี่ยวข้องเข้ากลุ่มนี้เท่านั้น

## ตั้งค่าการแท็กชื่อผู้ให้คำปรึกษาในไลน์กลุ่ม

เมื่อมีคิวใหม่เข้ามาสำหรับผู้ให้คำปรึกษาคนใด ระบบสามารถ @แท็กชื่อ LINE ของคนนั้นในกลุ่มให้อัตโนมัติ (นอกเหนือจากการ์ดแจ้งเตือนปกติ) เพื่อให้แน่ใจว่าคนที่เกี่ยวข้องเห็นแน่ๆ วิธีตั้งค่า:

1. ให้ผู้ให้คำปรึกษาคนนั้น **เพิ่มบัญชี Official Account ของระบบเป็นเพื่อน** ก่อน (สแกน QR หรือค้นหาจาก LINE ID ของบัญชี) — ถ้าไม่เพิ่มเป็นเพื่อน ระบบจะดึง User ID ไม่ได้
2. ในกลุ่ม LINE ที่เชื่อมกับระบบ ให้ผู้ให้คำปรึกษาคนนั้นพิมพ์คำว่า `ไอดีของฉัน` บอทจะตอบกลับ LINE User ID ส่วนตัวมาในแชท (เห็นเฉพาะคนพิมพ์)
3. เอา User ID ที่ได้ไปกรอกในหน้าแอดมิน > **ผู้ให้คำปรึกษา** ที่ช่อง "LINE User ID (สำหรับแท็กชื่อ)" ของคนนั้น แล้วกด **บันทึก**
4. ตั้งแต่นั้น เมื่อมีคิวใหม่เข้ามาสำหรับผู้ให้คำปรึกษาคนนี้ บอทจะส่งข้อความแท็กชื่อในกลุ่มก่อนการ์ดแจ้งเตือนปกติทันที

ผู้ให้คำปรึกษาที่ไม่ได้ตั้งค่า LINE User ID ไว้ จะไม่มีการแท็กชื่อ แต่การ์ดแจ้งเตือนปกติจะยังส่งเข้ากลุ่มตามเดิม

## เวรแบบคู่ (โครงการเพื่อนวัยใส)

ผู้ให้คำปรึกษาจับคู่กันแบบตายตัว 1 คิวจะมีผู้ให้คำปรึกษา 2 คนพร้อมกัน ผู้จองเห็นชื่อและรูปของทั้งคู่ตอนกดดูคิว

1. **นำเข้ารายชื่อ** — หน้าแอดมิน > ผู้ให้คำปรึกษา > วางรายชื่อบรรทัดละ 1 คน (`ชื่อ,ตำแหน่ง/ความถนัด,ลิงก์รูป`) ชื่อซ้ำจะถูกข้าม
2. **จับคู่** — ที่ตารางผู้ให้คำปรึกษา เลือกคอลัมน์ "คู่เวร" ของคนใดคนหนึ่ง ระบบจะผูกให้ทั้งสองฝั่งอัตโนมัติ (1 คนมีคู่ได้ 1 คน)
3. **สร้างคิวหมุนเวียน** — หน้าแอดมิน > จัดการคิว > "สร้างคิวหมุนเวียนคู่อัตโนมัติ" เลือกช่วงวันที่ วันศุกร์ ช่วงเช้า/บ่าย และความยาวคิว ระบบจะเติมทุกชั่วโมงด้วยคู่ตามลำดับที่สร้าง วนซ้ำจนครบ ข้ามวันปิดทำการและเวลาที่มีคิวอยู่แล้ว
4. **รูป** — ตอนนี้ใส่เป็นลิงก์รูป (ยังไม่มีอัปโหลด เพราะ Railway ไม่มีดิสก์ถาวร ต้องใช้ที่เก็บรูปภายนอก เช่น Cloudinary)
5. **แท็กในไลน์กลุ่ม** — ให้แต่ละคนพิมพ์ `ลงทะเบียน <ชื่อ>` ในกลุ่ม (ชื่อต้องตรงกับที่แอดมินบันทึก) บอทจะผูก LINE User ID ให้เอง เมื่อมีคิวใหม่บอทจะแท็กทั้งคู่

การเปลี่ยนคู่ภายหลังไม่กระทบคิวที่สร้างไปแล้ว (คิวเก็บคู่ ณ ตอนสร้าง)

## หน้าลงเวร / สลับเวร (LIFF)

ผู้ให้คำปรึกษากดลิงก์จากไลน์ ระบบรู้ว่าเป็นใครและผูก LINE ID ให้เอง จากนั้นลงเวร ยกเลิกเวร หรือขอสลับเวรได้เอง (ลิงก์: `https://liff.line.me/<LIFF_ID>`)

**การทำงาน**
- แอดมินสร้าง "เวรว่าง" (หน้าจัดการคิว > เลือก "สร้างเวรว่าง ให้ผู้ให้คำปรึกษาลงเอง")
- 1 เวรมี 2 ที่นั่ง ผู้ให้คำปรึกษาลงชื่อ **ทีละคน** ใครกดก่อนได้ที่นั่งก่อน ไม่ต้องจับคู่ล่วงหน้า
- เวรจะ **เปิดให้ผู้ขอรับคำปรึกษาจองก็ต่อเมื่อมีผู้ให้คำปรึกษาครบ 2 คน** (ลงแค่คนเดียวจะยังไม่ขึ้นให้จอง และการ์ดตารางในไลน์ก็ไม่แสดง)
- ถ้าคนหนึ่งยกเลิกจากเวรที่ครบ 2 คน อีกคนอยู่ต่อ เวรจะกลับไปรออีก 1 คนและปิดการจองอัตโนมัติ
- ขอสลับเวรเป็นรายคน: เลือกคนที่อยากสลับด้วย อีกฝ่ายกดยอมรับหรือปฏิเสธ ถ้ายอมรับ ทั้งสองคนสลับที่นั่งกัน
- ยกเลิก/สลับไม่ได้ถ้าเวรนั้นมีผู้จองแล้ว หรือใกล้ถึงเวลาเกินกว่าที่แอดมินกำหนด
- แอดมินตั้งค่าได้ที่ หน้าแอดมิน > ตั้งค่า > "กติกาการลงเวร": จำนวนเวรสูงสุดที่แต่ละคนถือไว้พร้อมกัน (ค่าเริ่มต้น 2) และเวลาล่วงหน้าที่ยกเลิก/สลับได้ (ค่าเริ่มต้น 24 ชม.) ใส่ 0 = ไม่จำกัด
- ทุกเหตุการณ์ (ลงเวร เวรครบ 2 คน ยกเลิก ขอสลับ สลับสำเร็จ) ประกาศเข้าไลน์กลุ่มและแท็กคนที่เกี่ยวข้อง
- การจับคู่ในหน้า "ผู้ให้คำปรึกษา" เป็นตัวเลือก ใช้เฉพาะโหมด "จัดคู่หมุนเวียนอัตโนมัติ" ที่แอดมินสั่งสร้างเวรให้ทั้งเทอมในครั้งเดียว

**ตั้งค่า (ทำครั้งเดียว)**
1. ไปที่ [LINE Developers Console](https://developers.line.biz/console/) เลือก **Provider เดียวกับ** ช่อง Messaging API ของบอท (สำคัญมาก ถ้าคนละ Provider ID จะไม่ตรงกันและแท็กชื่อไม่ได้)
2. สร้างช่องใหม่ชนิด **LINE Login** (Web app) แล้วคัดลอก **Channel ID** ไปใส่ตัวแปร `LINE_LOGIN_CHANNEL_ID` บน Railway
3. ในช่อง LINE Login แท็บ **LIFF** กด Add: Endpoint URL = `https://<โดเมนของคุณ>/me`, Size = Full, Scope = เปิด `openid` (และ `profile`) จากนั้นคัดลอก **LIFF ID** ไปใส่ตัวแปร `LIFF_ID`
4. เปลี่ยนสถานะช่อง LINE Login จาก Developing เป็น **Published** (ถ้าไม่ทำ คนที่ไม่ได้เป็นผู้ดูแลช่องจะเข้าไม่ได้)
5. ส่งลิงก์ `https://liff.line.me/<LIFF_ID>` ให้ผู้ให้คำปรึกษาในกลุ่ม ครั้งแรกแต่ละคนกรอก **ชื่อเล่น ชื่อจริง และอัปโหลดรูป** ในหน้าลงเวรหน้าเดียว (รูปถูกย่อในเครื่องแล้วเก็บในฐานข้อมูล ไม่ต้องใช้ที่เก็บรูปภายนอก) ผู้มาขอรับคำปรึกษาจะเห็นรูป ชื่อจริง และชื่อเล่นตอนเลือกเวลา แก้ไขภายหลังได้ที่ปุ่ม "แก้ไขรูป/ชื่อ" ถ้าแอดมินบันทึกชื่อไว้แล้วให้เลือก "แอดมินกรอกชื่อของฉันไว้แล้ว" เพื่อผูกบัญชี (ผูกแล้วถาวร ถ้าผูกผิดให้แอดมินล้างช่อง LINE User ID ในหน้า "ผู้ให้คำปรึกษา")

> หมายเหตุ: ใครก็ตามที่ได้ลิงก์จะลงทะเบียนเป็นผู้ให้คำปรึกษาได้เอง จึงควรแจกลิงก์เฉพาะในกลุ่มผู้ให้คำปรึกษา หากมีคนแปลกปลอมลงทะเบียน แอดมินกดปิดใช้งานหรือลบได้ในหน้า "ผู้ให้คำปรึกษา"

## ตั้งค่าอีเมลยืนยันการจอง (Resend)

1. สมัครบัญชีฟรีที่ [resend.com](https://resend.com) (ไม่ต้องใช้บัตรเครดิต)
2. สร้าง API key แล้วนำไปใส่ใน `RESEND_API_KEY`
3. (ไม่บังคับ) ถ้าต้องการให้อีเมลส่งจากโดเมนของมหาวิทยาลัยเอง ให้ไป verify โดเมนใน Resend ก่อน แล้วตั้งค่า `RESEND_FROM_EMAIL` เป็นอีเมลจากโดเมนนั้น — ถ้าไม่ตั้งค่า ระบบจะส่งจาก `onboarding@resend.dev` แทน (ใช้ได้แต่ผู้รับบางรายอาจเห็นเป็นอีเมลทดสอบ)
4. เมื่อตั้งค่าเสร็จ ทุกครั้งที่การจองถูกยืนยัน (จากหน้าแอดมินหรือปุ่มในไลน์กลุ่ม) ระบบจะส่งอีเมลยืนยันไปยังอีเมลของผู้จองโดยอัตโนมัติ — ถ้าไม่ได้ตั้งค่า `RESEND_API_KEY` ระบบจะข้ามการส่งอีเมลโดยไม่มี error

## โครงสร้างระบบหลัก

- `src/app/page.tsx` + `src/components/BookingCalendar.tsx` — หน้าปฏิทิน/จองคิวสำหรับผู้ใช้บริการ
- `src/app/admin/**` — หน้าแอดมิน (ป้องกันด้วย `src/proxy.ts` + session cookie)
- `src/app/api/**` — REST API สำหรับทั้งฝั่งผู้ใช้และแอดมิน
- `src/lib/line.ts` — ฟังก์ชันส่ง/รับข้อความ LINE Messaging API และสร้าง Flex Message
- `prisma/schema.prisma` — โมเดลข้อมูล (Counselor, Slot, Booking, ClosedDate, Admin)

## Deploy บน Supabase + Vercel (ฟรี)

ฐานข้อมูลอยู่ที่ [Supabase](https://supabase.com/) ส่วนเว็บ (Next.js) รันบน [Vercel](https://vercel.com/)

1. **Supabase:** สร้างโปรเจกต์ใหม่ ตั้งรหัสผ่านฐานข้อมูลแล้วจดไว้ จากนั้นกดปุ่ม **Connect** ที่ด้านบน คัดลอกสตริงเชื่อมต่อ 2 แบบ:
   - **Transaction pooler** (พอร์ต 6543) → ใช้เป็น `DATABASE_URL` ต่อท้ายด้วย `?sslmode=no-verify`
   - **Session pooler** (พอร์ต 5432) → ใช้เป็น `MIGRATE_DATABASE_URL` ต่อท้ายด้วย `?sslmode=require`
   (ถ้ารหัสผ่านมีอักขระพิเศษ เช่น `@` `#` ต้อง URL-encode)
2. **Vercel:** Add New → Project → เลือก repo นี้ (Framework = Next.js สคริปต์ `vercel-build` รันแค่ `next build` ไม่แตะฐานข้อมูล)
   - **สร้างตาราง:** ถ้าเครื่อง build ต่อ Supabase ตรงๆ ไม่ได้ ให้วางไฟล์ `prisma/migrations/*/migration.sql` ตามลำดับชื่อโฟลเดอร์ใน SQL Editor ของ Supabase หรือรัน `npm run db:migrate` จากเครื่องที่ตั้ง `MIGRATE_DATABASE_URL` ไว้
3. ตั้ง Environment Variables ใน Vercel: `DATABASE_URL`, `MIGRATE_DATABASE_URL`, `SESSION_SECRET`, `APP_BASE_URL` (โดเมนที่ Vercel ให้), `LINE_*`, `LINE_LOGIN_CHANNEL_ID`, `LIFF_ID` (ดูส่วนตั้งค่า LINE ด้านบน) แล้วกด Deploy
4. สร้างแอดมินคนแรก: ในเครื่องที่มี Node ให้ตั้ง `DATABASE_URL` เป็นสตริงเชื่อมต่อของ Supabase แล้วรัน `npm run db:seed`
5. ไปแก้ **Endpoint URL** ของ LIFF และ Webhook URL ของ LINE Messaging API ให้เป็นโดเมนใหม่ (`https://<โดเมน>/me` และ `https://<โดเมน>/api/line/webhook`)

> หมายเหตุ: แพลนฟรีของ Supabase จะพักโปรเจกต์ถ้าไม่มีการใช้งานนานหลายวัน ถ้าเว็บเข้าไม่ได้ให้เข้า dashboard แล้วกด Restore

## Deploy บน Railway (ทางเลือกเดิม)

แอปนี้เป็น Next.js server ธรรมดา (ไม่ใช่ static export) รันบน Node.js — ขั้นตอน deploy บน [Railway](https://railway.com/):

1. สร้างโปรเจกต์ใหม่บน Railway แล้วเลือก **Deploy from GitHub repo** ชี้ไปที่ repo นี้
2. เพิ่ม **PostgreSQL** เข้าโปรเจกต์เดียวกัน (New → Database → PostgreSQL) Railway จะสร้างตัวแปร `DATABASE_URL` ให้อัตโนมัติ
3. ในบริการของเว็บแอป (service) ไปที่ **Variables** แล้วตั้งค่า:
   - `DATABASE_URL` → อ้างอิงจากตัวแปรของ Postgres ที่สร้างไว้ (Railway จะเสนอให้เชื่อมอัตโนมัติ หรือใส่ `${{Postgres.DATABASE_URL}}`)
   - `SESSION_SECRET` → สุ่มค่าใหม่ เช่นรันคำสั่ง `openssl rand -base64 32`
   - `LINE_CHANNEL_ACCESS_TOKEN`, `LINE_CHANNEL_SECRET`, `LINE_GROUP_ID` → ตามขั้นตอนหัวข้อ "ตั้งค่าการแจ้งเตือน LINE กลุ่ม" ด้านบน
   - `APP_BASE_URL` → โดเมนจริงที่ Railway ให้มา เช่น `https://your-app.up.railway.app` (หรือ custom domain ถ้าผูกไว้)
4. Railway จะรัน `npm install` (ซึ่งจะรัน `prisma generate` ให้อัตโนมัติผ่าน `postinstall`) แล้ว `npm run build` และ `npm run start` — คำสั่ง `start` ถูกตั้งให้รัน `prisma migrate deploy` ก่อนเปิดเซิร์ฟเวอร์ทุกครั้ง ดังนั้น schema จะอัปเดตให้เองเมื่อ deploy ใหม่
5. หลัง deploy สำเร็จครั้งแรก เปิด **Shell** ของ service บน Railway (หรือรันผ่าน `railway run`) แล้วสั่ง:
   ```bash
   npm run db:seed
   ```
   เพื่อสร้างบัญชีแอดมินแรก (ตั้ง `SEED_ADMIN_USERNAME`/`SEED_ADMIN_PASSWORD` เป็นตัวแปรใน Railway ก่อน seed ถ้าต้องการเปลี่ยนจากค่า default)
6. เข้า `https://<โดเมนของคุณ>/admin/login` เพื่อ login ด้วยบัญชีที่ seed ไว้ แล้วไปที่ **ตั้งค่า > เปลี่ยนรหัสผ่านแอดมิน** เพื่อ**เปลี่ยนรหัสผ่านทันที**
7. ตั้งค่า Webhook URL ของ LINE Official Account เป็น `https://<โดเมนของคุณ>/api/line/webhook` แล้วทดสอบส่งข้อความในหน้าแอดมิน > ตั้งค่า
8. เข้าหน้าแอดมิน เพิ่มผู้ให้คำปรึกษาจริง + สร้างคิวว่างจริง แล้วลองจองทดสอบ 1 ครั้งเพื่อดูว่าข้อความ LINE เข้ากลุ่มจริง

### Deploy ครั้งต่อไป

ทุกครั้งที่ push โค้ดเข้า branch ที่ผูกไว้ Railway จะ build และ deploy ให้อัตโนมัติ (รวมถึงรัน migration ใหม่ให้ผ่าน `prisma migrate deploy` ในคำสั่ง start) — ถ้าแก้ `prisma/schema.prisma` ให้รัน `npx prisma migrate dev --name <ชื่อ>` ในเครื่อง dev ก่อน เพื่อสร้างไฟล์ migration ใหม่แล้ว commit เข้า repo ด้วย
